Assumptions made where prompt 06 did not settle the point
==============================================================================

 1. Grid clock range is [[time], [time]): the [time] row is excluded. Rows are the
    aligned 5-min rows that exist (none in the [date] gap).
 2. 'Inside a session or within 2 h after one' uses EVERY explore session in
    sessions.csv, usable or not, any category: rows in [start, end + 2 h].
 3. Label(t, H) = 1 if any explore session (usable or not) starts in (t, t + H],
    a start exactly H min ahead included. 'Sessions caught' counts usable
    sessions only; a firing before an unusable session is not a false alarm.
 4. Caught = fired at any GRID row in [start - H, start). Rows before [time] or
    inside the 2 h after an earlier session are not in the grid, so a session
    there has fewer chances; the count of such sessions is printed in part 0.
 5. R1 is horizon-dependent: at t the candidate 30-min clock slots are those
    overlapping (t, t + H] (fixed bins :00 and :30, clipped to the same day);
    the rule fires if any candidate slot had a same-weekday start on >= 2 of
    the previous 4 weeks. History = all explore sessions in sessions.csv
    (including the short window-0 gym entries), by exact start slot, so a
    start at [time] one week and [time] the next fall in different slots.
    Weeks before the data (first 4 weeks) and weeks in the April gap count 0.
 6. R2 'last 15 min' = rows t - 10, t - 5, t (the row t covers [t, t + 5));
    'last 10 min' = mean hr_mean over rows t - 5 and t with missing rows
    skipped; no HR in either row -> the HR part cannot fire. Baseline uses
    rows [time]-[time] of the same calendar day (so rows [time]-[time] see a
    baseline that includes readings up to [time]); fallback = median of the
    previous 7 calendar days' own baselines; if none, the HR part cannot fire.
 7. Gate = bolus_u + est_basal_u summed over rows [t - 4 h, t) (48 rows, the
    start row excluded, as in compute_features); partial after the April gap
    and at [time] on [date] only as far as rows exist; NaN est_basal_u = 0.
 8. False-alarm rows = fired and label 0. False-alarm episodes = maximal runs
    of consecutive firing grid rows (exactly 5 min apart; an excluded row or
    the [time] -> [time] break ends a run) in which no row has label 1. A run
    that starts early and ends inside the horizon of a real session is not a
    false alarm even though its first rows have label 0.
 9. Weeks = distinct grid dates / 7 (207 dates = 29.6 weeks); the April
    gap is not counted as time.
10. Two leads. lead = start minus the FIRST firing grid row in [start - H,
    start), capped at H by construction (R1 fires continuously, so it sits at
    H). leadrun = start minus the first row of the consecutive firing run that
    contains that row, i.e. when the alert actually came up; for R1 at
    horizon H this is bounded by H + 30 (slot width) unless a neighbouring
    slot also qualifies.
11. 'Usual training days' come from the private settings (usual_training_times:
    weekday, time of day and season per slot; withheld here); an episode is
    placed by its first row.
12. The one cycling session ([date]) is unusable (real gap inside its span), so
    cycling appears in the history, labels and exclusion but not as a positive;
    the cycling column is therefore absent from the caught tables.
13. 'gate alone (ref)' is printed for reference only: it is not one of the
    three rules and it is not a prediction of exercise.
