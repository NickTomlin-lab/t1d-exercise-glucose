Assumptions made where the prompts did not settle the point
==============================================================================

 1. Merge gap is idle time: next run start minus (previous run's last row + 5 min).
    Two runs are merged when that idle time is <= 30 min.
 2. 'Before start' windows are half-open [start - N, start): the start row is
    excluded from the bolus/carb sums, min_prev2h, mins_below4_prev24h and
    suspend_frac_prev60. bolus_iob_u and est_basal_iob_u are read from the
    start row itself (they are state at that moment).
 3. slope30 / slope15 are anchored on the row that supplied g0 (g0 minus the
    reading 30/15 min before that row). If that earlier reading is missing the
    slope is NaN, not interpolated.
 4. mins_since_bolus / mins_since_meal look back 24 h strictly before start and
    return 1440 when nothing is found.
 5. 'The 2 h after end' = rows in (end, end + 120]; 'end + 2 h to end + 12 h' =
    rows in (end + 120, end + 720]. Rows past the end of the data (or into the
    April gap) are simply absent; for outcome_missing_frac they count as
    missing against the expected row count, for low_late they are ignored.
 6. window 3 ([date] - [date]) starts immediately after window 2, so the
    prospective split and the window-2/3 boundary coincide and no session
    can be merged across it.
 7. hrs_since_prev_session is computed across the April gap as a real elapsed
    time (the first session of window 2 gets ~17 days x 24 h).
 8. hr_mean_session is the unweighted mean of the 5-min hr_mean values that
    are present; sessions with no HR at all get NaN.
 9. dow uses the dataset's own column at the start row ([weekday] = 0).
10. Two rows carry a workout_cat with workout_min == 0; per rule 1 they are
    not part of any run.
11. n_parts counts grid runs merged, as specified, but build_dataset.py has
    already fused watch workouts that were split seconds apart, so n_parts is
    1 everywhere. n_workouts (from processed/workouts_clean.csv) counts the
    raw same-category watch workouts overlapping the session instead.
12. flag_in_span, flag_reason, rows_missing_in_span and usable_v1 are kept in
    sessions.csv as diagnostics. flag_reason still names pod_change when it
    occurs, but pod_change no longer affects usable.
13. cat2 uses the calendar date of the session start only ([date] - [date]
    inclusive = indoor), with no check against duration or venue.
14. meal_band and prevlow_band boundaries are inclusive at the upper edge as
    written in prompt 02 (e.g. 120 -> 0-2h, 121 -> 2-4h; 30 -> 1-30).

8. Assumptions made where prompt 02 did not settle the point
==============================================================================

 1. Control 'end' = control start + (session end - session start), so the
    control has the same number of rows as the session; its outcome span is
    start..end+2h exactly as for sessions.
 2. 'Entirely on or before [date]' is applied to control end + 2 h
    (the whole outcome span), not just the control start.
 3. The exercise-free check uses every session in sessions.csv (all three
    cats, usable or not, any split) against [control start - 24 h, control
    end + 2 h]. Walking is not a session and so is not excluded.
 4. Candidate dates are ordered by |days| then by sign (earlier date first
    on ties), and the first 3 that pass every check are kept.
 5. Same data window is checked at both the control start and the control
    end + 2 h rows.
 6. Bootstrap ratio: sessions are resampled with replacement; a draw whose
    control rate is 0 gives an infinite ratio and is dropped from the
    percentile interval (the count of such draws is printed).
 7. The per-cat2 comparison uses the same 2,000-draw bootstrap per group,
    with the same generator continued (seeded once at the top).
 8. Doubtful cat2 in part 7 lists indoor-season cricket > 120 min (as the
    prompt suggests) and, as an extra, outdoor-season cricket <= 90 min.
 9. Part 6 session rates use all usable explore sessions, not only those
    with a control, so they match part 2.
10. Control features are computed with the same compute_features() as
    sessions, so hr_mean_session / steps_session etc. exist but are not
    written; only the requested columns plus outcome_missing_frac, usable,
    window, cat2, start, end and duration_min are kept.
